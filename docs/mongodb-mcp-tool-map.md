# MongoDB MCP Tool Map

## Selected Partner Track

MongoDB Track

---

## Overview

YOUSUN Amicus uses MongoDB as the main system of record for loan applications, borrower profiles, agent analysis, generated reports, and rescue-before-default plans.

The purpose of this document is to explain how MongoDB MCP can support the agent workflow by giving the agent controlled tool-based access to stored financial data and generated outputs.

This file is prepared for judge-facing documentation and project explanation. It shows how MongoDB is connected to the agentic workflow instead of being used only as a simple storage layer.

---

## Why MongoDB Fits YOUSUN Amicus

YOUSUN Amicus works with different types of data:

- Loan application data
- Business and borrower details
- Financial Twin analysis
- Future Mirror stress-test results
- Dynamic EMI plans
- Generated reports
- Rescue-before-default actions

MongoDB is a good fit because this data is flexible and may grow over time. Some records are structured, such as loan amount, sales, EMI, and risk score. Other records are more document-based, such as generated reports, explanations, and rescue recommendations.

MongoDB allows the project to store both types of information in a clean and scalable way.

---

## MongoDB Role in the Agent Workflow

MongoDB is used as the system of record.

The agent reads application data from MongoDB, runs analysis, generates reports, and saves the results back to MongoDB.

The workflow is:

```txt
MongoDB Data → Agent Tools → Financial Analysis → Report Generation → MongoDB Storage
```

This makes the loan review process easier to trace, audit, and explain.

---

## MongoDB MCP Role

MongoDB MCP is positioned as the tool-access layer for the agent.

Instead of the agent using hardcoded information, MongoDB MCP can allow the agent to access real application data through defined tools.

The agent can use MongoDB MCP-style tools to:

- Fetch loan applications
- List pending applications
- Save analysis results
- Fetch generated reports
- Save generated reports
- Create rescue-before-default plans

This makes the agent workflow more realistic, explainable, and connected to actual data.

## Main Collections

### 1. users

The `users` collection stores demo bank officer and role information.

This collection can be used later for authentication, role-based access, and officer activity tracking.

Example document:

```json
{
  "id": "USER-001",
  "name": "Demo Bank Officer",
  "email": "officer@yousun-amicus.demo",
  "role": "Credit Officer"
}
```

Possible use cases:

- Identify the bank officer
- Track who generated a report
- Support role-based access in future versions

---

### 2. loan_applications

The `loan_applications` collection stores borrower and business loan application data.

This is one of the most important collections in the project because the agent starts the workflow from this data.

Example document:

```json
{
  "id": "APP-001",
  "businessName": "Rahim Fashion House",
  "ownerName": "Md. Rahim Uddin",
  "businessType": "Retail Apparel",
  "location": "Dhaka, Bangladesh",
  "requestedLoan": 1500000,
  "recommendedLoan": 900000,
  "existingEmi": 12000,
  "averageMonthlySales": 420000,
  "riskLevel": "Medium",
  "status": "AI Review Pending",
  "seasonality": "High sales during Eid and lower sales after seasonal campaigns"
}
```

Possible use cases:

- List all applications
- Fetch one application by ID
- Review borrower details
- Check requested loan amount
- Review sales and EMI information
- Read risk level and seasonality
- Update application status

---

### 3. agent_analyses

The `agent_analyses` collection stores outputs generated by the YOUSUN Amicus agent.

This collection helps keep the agent workflow auditable because the calculated analysis is saved after each review.

Example document:

```json
{
  "applicationId": "APP-001",
  "analysis": {
    "financialTwinScore": 736,
    "businessHealthScore": 82,
    "approvalReadinessScore": 72,
    "safeLoanAmount": 900000,
    "riskLevel": "Medium",
    "recommendation": {
      "decisionSupport": "Recommended with reduced loan amount",
      "reason": "Requested loan amount creates repayment pressure during low-sales months"
    }
  },
  "generatedBy": "YOUSUN Amicus Agent",
  "updatedAt": "2026-06-06T00:00:00.000Z"
}
```

Possible use cases:

- Save Financial Twin result
- Save Future Mirror stress-test output
- Save safe loan recommendation
- Save Dynamic EMI result
- Save rescue-before-default analysis
- Review previous analysis for the same borrower

---

### 4. reports

The `reports` collection stores generated reports.

YOUSUN Amicus can generate different reports for different audiences, such as a bank officer, borrower, or risk manager.

Example document:

```json
{
  "id": "RPT-BANK-APP-001",
  "applicationId": "APP-001",
  "title": "Bank Officer Credit Memo",
  "type": "bank_memo",
  "audience": "Bank Officer",
  "summary": "Recommended approval support with reduced loan amount, dynamic EMI, and monitoring.",
  "createdAt": "2026-06-06T00:00:00.000Z",
  "generatedBy": "YOUSUN Amicus Agent"
}
```

Possible report types:

- Bank Officer Credit Memo
- Customer-Friendly Loan Guidance
- Rescue Before Default Report

Possible use cases:

- Fetch all reports
- Fetch one report by ID
- Fetch reports by application ID
- Save bank officer memo
- Save customer summary
- Save rescue report

---

### 5. rescue_plans

The `rescue_plans` collection stores early support actions before a borrower reaches default.

This collection supports the Rescue Before Default concept.

Example document:

```json
{
  "applicationId": "APP-001",
  "distressLevel": "Medium",
  "signals": [
    "Sales down 35%",
    "EMI delayed twice"
  ],
  "customerAction": "Request temporary EMI support and submit updated cashflow details",
  "bankAction": "Offer a 4-month lower EMI plan with close monitoring",
  "avoidAction": "Avoid immediate legal notice while the borrower is willing to cooperate",
  "recoveryProbability": 76,
  "generatedBy": "YOUSUN Amicus Agent"
}
```

Possible use cases:

- Create rescue-before-default plan
- Store distress signals
- Suggest customer-side action
- Suggest bank-side action
- Store avoid-action warning
- Track recovery probability

# Agent Tool Mapping

## Tool 1: getLoanApplication

### Purpose

Fetch a single loan application from MongoDB using the application ID.

### Input

```json
{
  "applicationId": "APP-001"
}
```

### Output

```json
{
  "id": "APP-001",
  "businessName": "Rahim Fashion House",
  "ownerName": "Md. Rahim Uddin",
  "requestedLoan": 1500000,
  "averageMonthlySales": 420000,
  "existingEmi": 12000,
  "riskLevel": "Medium",
  "seasonality": "High sales during Eid and lower sales after seasonal campaigns"
}
```

### Agent Use

The agent uses this tool at the beginning of the loan review workflow.

It gives the agent the factual borrower and business data needed for Financial Twin analysis and Future Mirror simulation.

---

## Tool 2: listLoanApplications

### Purpose

List loan applications for the bank officer dashboard.

### Input

```json
{
  "status": "AI Review Pending"
}
```

### Output

```json
[
  {
    "applicationId": "APP-001",
    "businessName": "Rahim Fashion House",
    "requestedLoan": 1500000,
    "status": "AI Review Pending"
  }
]
```

### Agent Use

The agent uses this tool when a bank officer wants to see available loan applications.

This tool helps the officer choose which application should be reviewed first.

---

## Tool 3: saveAgentAnalysis

### Purpose

Save the agent's calculated analysis to MongoDB.

This includes Financial Twin, Future Mirror, Dynamic EMI, recommendation, and rescue planning results.

### Input

```json
{
  "applicationId": "APP-001",
  "analysis": {
    "financialTwin": {
      "score": 736,
      "businessHealthScore": 82,
      "approvalReadinessScore": 72
    },
    "futureMirror": [
      {
        "scenario": "Normal Case",
        "risk": "Medium"
      },
      {
        "scenario": "Stress Case",
        "risk": "High"
      }
    ],
    "recommendation": {
      "safeLoanAmount": 900000,
      "decisionSupport": "Recommended with reduced loan amount"
    },
    "dynamicEmi": {
      "type": "Seasonal EMI",
      "reason": "Sales are not equal across all months"
    },
    "rescuePlan": {
      "distressLevel": "Medium"
    }
  }
}
```

### Output

```json
{
  "success": true,
  "message": "Agent analysis saved"
}
```

### Agent Use

The agent uses this tool after completing the main loan review workflow.

This makes the analysis available for report pages, future review, and audit.

---

## Tool 4: getReportsByApplication

### Purpose

Fetch all reports connected to one loan application.

### Input

```json
{
  "applicationId": "APP-001"
}
```

### Output

```json
[
  {
    "id": "RPT-BANK-APP-001",
    "title": "Bank Officer Credit Memo",
    "audience": "Bank Officer"
  },
  {
    "id": "RPT-CUSTOMER-APP-001",
    "title": "Customer-Friendly Loan Guidance",
    "audience": "Customer"
  }
]
```

### Agent Use

The agent uses this tool when a reviewer wants to see all generated outputs for a borrower.

This is useful for both the reports page and the application detail page.

---

### Purpose

### Input

```json
{
  "applicationId": "APP-001",
  "type": "bank_memo",
  "title": "Bank Officer Credit Memo",
  "audience": "Bank Officer",
```

# Judge-Facing Explanation

YOUSUN Amicus uses MongoDB as more than a database. MongoDB works as the system of record for the full agent workflow.

The agent reads borrower applications from MongoDB, generates Financial Twin analysis, runs repayment stress simulation, prepares reports, and stores rescue-before-default plans.

MongoDB MCP is positioned as the tool-access layer that allows the agent to interact with real application data instead of relying only on static or hardcoded content.

This makes the workflow traceable, auditable, and easier for a bank officer or judge to understand.

---

# Responsible Data Positioning

YOUSUN Amicus uses stored data only for decision-support.

The system does not make final credit approval or rejection decisions. Final approval, restructuring, recovery, and customer communication must remain with authorized bank officers or risk managers.

The role of MongoDB in this project is to make the agent workflow reliable, reviewable, and connected to the actual loan application record.
